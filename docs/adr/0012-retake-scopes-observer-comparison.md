# A retake scopes the 360 comparison to responses since the current result

A Subject holds one current result, overwritten on retake (ADR-0004), and Observer responses are tied to the Subject rather than to a particular result (ADR-0003). Left alone, a retake would compare Observer reads gathered earlier against self words those Observers never saw. We considered three options: clearing Observer responses on retake, rotating the share token, or versioning results. We chose a light form of versioning that needs no schema change: the current result's `updatedAt` (stamped with the database clock, the same clock that stamps `observer_response.createdAt`) marks when it was taken, and the comparison report counts only responses recorded at or after that moment. Earlier responses stay in the database but are left out, and the report tells the Subject how many were set aside so a re-locked report isn't a mystery. We rejected clearing responses because it destroys Observer input irreversibly, and rejected rotating the token because it would silently break links already handed out (the property issue #8 deliberately kept). The share link therefore stays stable across retakes, and the ≥3 unlock gate applies to the current result's responses alone.
